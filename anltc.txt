When the Adobe Web SDK event tracking payload is inspected on any of the above components that fire a Link Click event:

The clickName dynamically reflects the actual rendered button or link text — not a hardcoded value. The value must be lower cased, trimmed, and not excessively long.

clickDestination If there is a value for this field on the clicked element, the value must always be a full URL. If there is a hashed component in the link href/destination, please include that, e.g. https://www.lumen.com/en-us/page.html#products. If there is no value (e.g. a toggle click) this value should be empty string.

clickLocation The value for this field will always be (one of) header, body or footer - this value should be “body” for all CDP hero.

clickContext DIA + LCV essentials (Identify what offer / card / module that CTA belonged to and provide a friendly name for reporting).

componentContext This value should match the name of the component, for this ticket it should be “content detail hero”

clickType is auto-populated with the values other, download, or exit. Be sure the value is one of these three only.

When the event fires for a single user interaction (one click), just one Link Click event is emitted — no duplicate events on a single click interaction.

Clicks on a non-anchor element may trigger a separate tracking call with an evar11 value. This is okay, as the payload in that tracking call should not contain anything which may falsely increment standard (anchor) Link Click events in reporting
